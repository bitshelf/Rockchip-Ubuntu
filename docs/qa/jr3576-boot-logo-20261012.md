# JR3576 ext4 bootfs logo verification

Replacing the SDK RKIMG boot partition with an ext4 bootfs removed the
resource-image path used to load `logo.bmp` and `logo_kernel.bmp`. The
Ubuntu bootfs now carries the original SDK files under `/logos/`, and
`0005-load-boot-logos-from-ext4-bootfs.patch` adds bounded filesystem reads
to the Rockchip U-Boot resource loader. Legacy RKIMG lookup remains the
fallback when the filesystem logo is absent.

Platform-asset staging accepts an optional, complete BMP pair from
`SDK_OUTPUT_DIR/extlinux/`. The files are covered by the asset and bootfs
SHA256 manifests. The validator rejects symlinks, oversized files,
unsupported bitmap headers, compressed pixels and truncated payloads.
GNOME image assembly requires the pair by default; explicit lab overrides
use `BOOTFS_REQUIRE_LOGOS=0`. A release must validate with
`BOOTFS_REQUIRE_LOGOS=1`, including when checking an existing bootfs.

The original SDK logos are build inputs, not tracked binary files:

The independent U-Boot build and FIT packaging passed. The 4 MiB U-Boot
payload SHA256 is
`7d2c86835348177d76b38fe9bb31abe42a32fb66263748b8edf9a26bbe786561`;
its write and full partition readback matched. The pre-write backup SHA256
is `a78a810e83641858bd3e1f791039af7dcb397813e6f675406fda6cc299c14bf7`.
Only U-Boot and the two bootfs logo files were updated for this check.

The controlled reboot log records both `Logo(Distro)` reads, a 1920×1080
HDMI mode, and the reserved `drm-logo` memory handed to Linux. The user
reported seeing the logo and subsequently the desktop. Runtime checks
confirmed active GDM and RKAIQ on the Ubuntu RT kernel. This is a lab
bootloader/bootfs test, not promotion of a rebuilt GNOME release image.

Host QA passed `tests/host/test-boot-logos.py`,
`tests/host/test-build-bootfs.sh`, and `tests/host/test-stage-sdk-assets.sh`.
Raw evidence and the backup remain under SDK workspace
`output/ubuntu-desktop-jr-20261011/qa/`, including
`uboot-logo-boot.serial.log`, `uboot-logo-write.log`,
`uboot-logo-postboot-runtime.log`, and the three host-test logs.

The initial logo dwell includes U-Boot's DSI initialization and boot menu;
the Linux startup check measured 6.865 s kernel plus 14.711 s userspace,
with graphical.target reached after 13.603 s userspace. This does not
measure power-on to visible desktop and does not certify a startup-time
threshold. Unused DSI is disabled later by the Linux overlay; applying
board display policy before U-Boot display probing remains follow-up work.
