# JR3576 Ubuntu Server 构建与板测

2026-10-10 开始，2026-10-11 完成。原生 ARM64 构建机为 192.168.1.209，
USB/串口主机为 192.168.1.105，DUT 为其 2002 串口连接的 JR3576。
最终系统是 Ubuntu 26.04.1 Server、Linux 6.1.141 #3，DUT DHCP 地址为
192.168.1.138。按用户要求完成 Server、英文首启及 OV13855 3A 服务验证。
基础板测 12 项通过，严格内核日志检查未通过；不能标记为所有硬件验收通过。

## 构建与写入

原生 Server rootfs QA、平台资产校验、overlay-root/bootfs 构建校验通过。
内核使用 `config/kernel/jr3576-server.config`，GPU 为 vendor Mali，禁用
RT group scheduling；应用 `docs/patches/kernel/` 中旧网格 ioctl 兼容补丁。
U-Boot 补丁与配置位于 `docs/patches/u-boot/` 和
`config/bootfs/jr3576-uboot.config`，修复早期 DTB 加载和未接入 ADC 下载键。

用户授权写入 boot/rootfs/userdata、清空 userdata，随后补充授权写入 uboot。
初次已初始化 userdata，后续更新只写 boot/rootfs，保留测试账号和文件。
未写 SPL/DDR loader、GPT、misc 或 recovery。最终摘要：

| 产物 | SHA256 |
| --- | --- |
| boot-rk3576.img | b01a62f48014721966ae04a4b6f50f52b60837aa14d6d421550db007848efcbb |
| ubuntu-26.04-server-arm64.rootfs.erofs.img | 3c1f7243d41da7986962bf3c127c7e052dd95a6fb9498651a08e15e8936b7006 |
| Kernel Image | 37fc879a43eff6e15d125c4a9d1976a7886522ec50efdcbc6a3aeb6a335d16bd |
| uboot-jr3576-extlinux.img | a78a810e83641858bd3e1f791039af7dcb397813e6f675406fda6cc299c14bf7 |

最终 rootfs 为 1,565,138,944 字节，Linux 从分区读取相同字节数计算 SHA256
完全一致。uboot 4 MiB 写后完整读回一致，并保留原分区备份。
Rockusb 读取物理 32 MiB 以后会返回 0xcc，因此不能用它验证 rootfs。
boot 是运行时读写挂载的 ext4，挂载会改变文件系统元数据；整分区运行后摘要
不能作为原始镜像的相等检查，板端 `/boot/Image` 摘要与构建内核一致。

## OV13855 ISP / 3A

CSI1 OV13855 位于 I2C3 0x36，芯片 ID 为 OV00d855。disable-DSI overlay 保留
共享 mipidcphy0；本次显式选用 OV13855-only 示例 overlay，禁用未接入的
OV5640 和相关虚拟管线。示例没有成为全局默认配置。

RKAIQ 6.30.4 的旧两缓冲区网格 ioctl（28 字节）在新内核（36 字节）返回
ENOTTY，导致 CAC 访问空指针；兼容补丁保留新接口并支持旧请求。板端 strace
和 GDB 确认原故障，最终两个请求均通过。旧 ISP3x IQ 同样不适合 ISP39。
生成的服务验证 IQ 采用 SDK ISP39 默认参数，保留 OV13855 的真实增益、曝光
寄存器换算、限值及延迟。生成方法见 `ISP.md`，输入及输出摘要保存在输出目录
`camera-iq/ov13855_default_default.json.provenance`，不纳入 Git。

最终验证通过：

- rkaiq_3A.service enabled/active，init、prepare、start 完成。
- 实时统计线程 xc:isp_3a_stats 为 SCHED_RR，优先级 20。
- 实际采集 90 帧 640×480 NV12，共 41,472,000 字节，90 次 DQBUF。
- 采集后观察 30 秒，PID 1196 不变，NRestarts=0，无线程创建失败或崩溃。
- EROFS 内和运行时 IQ 摘要均为 bc59d80d0bf8eeddd952095e1024a83fed2c9237dac1c0c5af10228e787ff082。

本次不验收画质、HDR 或量产调校。最终取流未见 AEC/AWB schema 错误，仍有
AIISP/BTNR 缓冲区与统计警告；不据此声明算法或降噪质量合格。

## 基础板测与剩余问题

最终镜像复测通过 firstboot、network、ADB、RGA、MPP、GStreamer RKMPP、V4L2、
RKNPU、headless EGL、ALSA 工具、update-engine 和内核诊断，共 12 项。
RKNPU 以 qa3576 非 root 用户完成 200 次推理，top1 class 156，概率 0.935059，
平均 4.25 ms、最大 4.58 ms；EGL 实际渲染器为 Mali-G52。update-engine 与
watchdog/pstore 的检查为只读，没有执行 OTA 或 watchdog reset。

严格 kernel-log-allowlist 未通过，保留原错误而未扩大白名单：ES8389 的 I2C/ASoC
寄存器访问 -6、VOP regulator/OPP、重复 Goodix 注册、零大小 logo 保留区、
RK806 power-off pinctrl、VENC devfreq 等。音频测试只证明工具与设备枚举，未证明
真实播放/录音。无线、显示、长期压力、断电恢复未测试。
调试期间在 DUT userdata 安装了 gdb/strace；基础镜像没有这些额外调试安装。
