# V4L2、v4l-utils 与 libv4l-rkmpp

镜像使用 Ubuntu 当前版本的 `v4l-utils` 源码，叠加 Rockchip libv4l plugin、
multi-plane 和 dma-buf 补丁，再从 SDK source archive 构建 `libv4l-rkmpp1`。
二者必须配套：未打补丁的 libv4l2 不具备该 plugin 所需的 mmap ABI。
构建器同时收集与 `v4l-utils` 精确版本绑定的 `libv4l2rds0t64`，避免只替换工具和
libv4l 主库后留下不可配置的软件包。

在 ARM64 Ubuntu 构建主机执行：

```bash
./scripts/build-local-debs.sh v4l-utils
# 通用构建器会按清单自动准备 SDK MPP development DEB。
./scripts/build-local-debs.sh libv4l-rkmpp
./scripts/stage-sdk-assets.sh
```

统一入口由 `config/local-debs/build.conf` 描述构建方式和输出包，产物写入
`SDK_OUTPUT_DIR/v4l/`。新增本地软件包时扩展配置和 Debian recipe，不再增加
`build-<package>.sh`、`stage-<package>.sh`、`install-<package>.sh` 三套入口。
`config/local-debs/packages.conf` 负责选择进入 platform-assets 的 DEB，
`config/local-debs/install.conf` 负责安装顺序、静态文件、服务和最小校验。

`rkmpp-video-nodes.service` 每次启动创建 `/dev/video-dec0` 与
`/dev/video-enc0`。它们是 libv4l-rkmpp 识别 decoder/encoder 角色的普通文件，
不是内核 video device；plugin 将其请求转换到 `/dev/mpp_service`。

## 目标 QA

独立于 Chromium 和 ISP 服务运行：

```bash
sudo /usr/libexec/ubuntu-v4l2-qa
```

脚本必须通过 libv4l2 wrapper 查询虚拟 decoder 并输出 `V4L2_RKMPP_OK`。
发现 rkisp mainpath/selfpath 时还会抓取 30 帧并输出 `V4L2_CAPTURE_OK`；也可显式
指定设备，便于替换 sensor 或 media graph：

```bash
sudo V4L2_CAPTURE_DEVICE=/dev/video33 V4L2_FRAME_COUNT=30 \
  /usr/libexec/ubuntu-v4l2-qa
```

V4L2 QA 只证明设备枚举、plugin ABI 和实际 buffer dequeue；3A 启动、sensor IQ
与画面变化由后续 RKISP/RKAIQ 功能 QA 负责。
